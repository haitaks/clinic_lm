# Интеграция мультилейбл-модели (Java, ONNX Runtime)

> Альтернатива авторегрессионной frame-модели (`model.onnx` + constrained
> decoding): один линейный прогон, без цикла генерации. Контракт повторяет
> привычную схему — векторизация на клиенте, в графе только классификатор.
> Тренировочная ветка: TF-IDF word(1,2) + словарь замен OOV; обучение —
> `train/train_multilabel.py` (ветка «(д) dict (экспорт)»), экспорт —
> `train/export_multilabel_onnx.py`.

## 1. Файлы

| Файл | Что это |
| :-- | :-- |
| `multilabel_model.onnx` | граф: `float32[None, 19839]` → вероятности 50 тегов |
| `multilabel_features.json` | словарь признаков (19 839), idf, порог |
| `multilabel_tags.json` | порядок выходов: группа + тег (50 позиций) |
| `oov_dict.json` | замены незнакомых слов (185 записей) |
| `multilabel_testvectors.json` | 10 фраз → ожидаемые теги (юнит-тест) |

## 2. Пайплайн на Java

```
text
  → oov_dict: заменить СЛОВА вне словаря признаков (см. 2.2)
  → векторизация (см. 2.1) → float32[19839]
  → multilabel_model.onnx → вероятности[50]
  → декодирование по группам (см. 3) → фрейм
```

### 2.1 Векторизация (описание = эталон в `train/export_multilabel_onnx.py::vectorize`)

1. `s = text.toLowerCase()` (без изменения «ё»);
2. токены: все вхождения `\w\w+` (2+ буквенно-цифровых символа подряд);
3. термы: каждый токен (униграмма) + биграмма соседних токенов,
   склеенная одним пробелом (`"запишите меня"`);
4. `tf = 1 + ln(count)` для термов с count ≥ 1 (натуральный логарифм);
5. `value = tf * idf[term]` (idf — из `multilabel_features.json`);
6. L2-норма вектора: `v /= sqrt(Σ v_i²)`;
7. отсутствующие в словаре термы игнорируются.

### 2.2 Словарь замен OOV

Для каждого токена входа: если токен есть в `oov_dict.json` **и** его нет
в `vocabulary` модели — заменить на значение. Служебные/известные слова не
трогать (защита от порчи известных фраз). Применять до векторизации.

## 3. Декодирование тегов (группы из `multilabel_tags.json`)

- **intent** (15 тегов): argmax по вероятностям группы. Если интент —
  `<YES>` / `<NO>` / `<UNSUPPORTED>`, фрейм голый: `INTENT <END_FRAME>`
  (специальность/симптомы/время не выводятся).
- **spec** (14 + `<UNKNOWN_SPECIALTY>`): argmax по группе; выводится
  только для нетривиальных интентов.
- **sym** (19): все теги с `prob >= 0.5` (порог в features.json; на val
  лучший микро-F1 симптомов был при 0.3 — можно снизить, если важнее
  полнота).
- **clar** (`<NEEDS_CLARIFICATION>`): `prob >= 0.5`.
- Порядок сборки строки фрейма:
  `INTENT SPEC (<TIME> факторы </TIME> | <T_UNKNOWN>) SYMPTOMS… [CLAR] <END_FRAME>`

## 4. Временной слот

Классификатор время НЕ предсказывает (решение проекта: время = хардкод).
Матчинг по таблице `TEMPORAL_ENTRIES` из `synth/vocab.py` — самый длинный
вход, найденный в тексте по границам слов (регистронезависимо, «ё»→«е»),
даёт канонические фактор-токены (`T_TOMORROW`, `T_H13_30`, …). Не найдено
ничего → `<T_UNKNOWN>`. Альтернативы «или» → фактор дня + `T_AMBIG`.

## 6. Проверка на вашей стороне

Юнит-тест: прогнать `multilabel_testvectors.json` через ваш пайплайн —
интент и набор тегов обязаны совпасть с ожидаемыми. Эталон векторизации
сходится со sklearn до машинного нуля, граф — до 1e-7 (fp32).
