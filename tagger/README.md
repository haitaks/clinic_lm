# Эксперимент: тегированная архитектура NLU (joint intent + tagging)

**НЕ основная модель.** Основная — frame-модель `train/` (см. корневой
README, секция «Модель и её текущее состояние»); этот контур — резерв и
площадка для экспериментов с BIO-разметкой.

Альтернатива seq2seq-GPT из `train/`: слова запроса размечаются тегами
`{O, SPEC, SYM, TIME}`, интент классифицируется по фразе целиком,
фрейм собирается детерминированной пост-обработкой (словарь синонимов,
табличный парсер времени). Идея: «раскидываем слова по тегам; незнакомое
слово — резолвим синонимом; тег принимает конкретное значение».

Директория самодостаточна (дублирование с `train/` сознательное);
GPT-модель и её пайплайн живут параллельно в `train/`.

## Почему теггер обходит GPT на OOD

Три механизма в сборке (не в сети!):

1. **Словарные спаны**: спаны SPEC/SYM мержатся из тегов модели И
   словарного скана иголок (невидимые синонимы «кожник», «дантист» —
   в словаре с ood-формами). TIME из словаря — только для валидных
   интентов (в негативах «завтра» встречается в «какая завтра погода»).
2. **Ревизия интента**: unsupported + найденная специальность/симптом —
   противоречие (настоящие негативы иголок не содержат — гарантирует
   валидатор генератора) → интент становится book.
3. **Сегментация спанов словарём**: подряд идущие симптомы без
   O-разрыва («голова раскалывается аллергия») режутся на ключи.

Сеть отвечает за то, что словарю недоступно: TIME-теги (контекст!),
несловарные выражения, интент на невидимых формулировках (0.795 без
ревизии → 1.000 с ней).

## e5-резолвер OOV (нейтрален, выключен по умолчанию)

`oov_resolver.py` + индекс `models/e5_index.npz`: multilingual-e5-small,
эмбеддинги 150 канонических поверхностей. Живую речь резолвит отлично
(«зуб разрывает»→toothache 0.92, «лор»→ent 0.93), НО ложные слова дают
столь же высокий скор («погода»→fever 0.89) — порог по косинусу
мусор не отделяет. В пайплайне резолвер видит только спаны, помеченные
тегом модели; строгий режим (SYM, порог 0.85) даёт OOD 0.890 против
0.900 без него — шум компенсирует пользу. Включается
`evaluate.py --resolver` (нужен transformers). Вывод: резолвер
заработает при более чистых тегах (см. «Дальше»).

## Файлы

| Файл | Роль |
|---|---|
| `annotate.py` | авторазметка: иголки → спаны → BPE-теги + интент; round-trip контроль |
| `model.py` | двунаправленный энкодер (6.8M) + головы intent/tags |
| `train_tagger.py` | обучение на DirectML (CPU-копии весов, самопроверка чекпойнта — уроки `train/train.py`) |
| `assemble.py` | сборка фрейма: словарь, TEMPORAL_FACTORS, ревизия интента, мерж спанов |
| `evaluate.py` | фрейм-метрики на всех наборах + сравнение с GPT-таблицей |
| `oov_resolver.py` | e5-резолвер + построение индекса |
| `export_tflite.py` | TF-зеркало → `models/tagger{,_int8}.tflite` + парность (fp32 1e-6, сквозной фрейм torch==tflite) |
| `gen_kotlin_vectors.py` | тест-векторы Kotlin: `models/kotlin_vectors.json` |
| `models/` | артефакты: tagger.pt, tflite (7.5 МБ int8, ОДИН forward против 7–15 шагов GPT), e5-индекс |
| `data/` | *.tags.jsonl (генерируются annotate.py, в git не нужны) |

Контракт tflite: вход `int64[1,128]` (BOS + bpe, хвост `<PAD>`), выходы
`intent float32[1,4]` + `tags float32[1,128,4]`; тег i-го токена =
`tags[0, i]`, позиции 0 — BOS. Сборку фрейма (словарь + правила) нужно
портировать на Kotlin — правила маленькие, словари берутся из
`synth/vocab.py`, тест — `models/kotlin_vectors.json` (15 кейсов с тегами
и фреймами от int8-модели).

## Запуск

```bash
.venv-tr/Scripts/python tagger/annotate.py                  # разметка + round-trip
.venv-tr/Scripts/python tagger/train_tagger.py --device dml --epochs 20
.venv-tr/Scripts/python tagger/evaluate.py                  # таблица метрик
.venv-tf/Scripts/python tagger/oov_resolver.py              # индекс e5 + тест
.venv-tf/Scripts/python tagger/export_tflite.py             # tflite + парность
.venv-tf/Scripts/python tagger/gen_kotlin_vectors.py        # тест-векторы
```

## Известные дыры (общие с GPT-моделью, из датасета)

- «отмени все мои записи» → UNSUPPORTED: в train нет короткой формы
  «отмени» и формулировки «все записи» (только «отмените запись к X»).
- Числовое время («в 15:00») — вне покрытия (в train цифр нет).
- Routing «симптом → врач» (PLAUSIBLE) здесь не включён — следующий шаг.
