# Менеджер диалога телефонии (регламент РГ-ТЕЛ-01)

Многошаговый менеджер диалога (МД) голосового ассистента регистратуры по
`скрипт.docx` (регламент РГ-ТЕЛ-01). Чистый Python без внешних
зависимостей; телефония (ASR/TTS/Asterisk) и МИС подключаются адаптерами.

## Архитектура: МД — маршрутизатор, разбор реплики — модель

- **NLU-модель** разбирает реплику пациента ЦЕЛИКОМ: интент,
  специальность, ФИО, дата рождения, полис, желаемые дата/время, да/нет,
  выбор варианта (`choice`), родство, флаги. Результат — `Frame`
  (`schema.py`).
- **Менеджер диалога** (`manager.py` + `scenarios/`) фрейм не парсит:
  он ведёт FSM по скрипту, задаёт эталонные реплики, выполняет операции
  МИС и эмитит действия (перевод с карточкой, SMS, завершение, обратный
  звонок). Интенты и адресаты перевода — читаемые имена (`book`,
  `reschedule`, `operator`, `senior`…), коды регламента (I-xx, R-xx, С-xx)
  в коде не используются.
- **Выбор врача — только по таблице 2.3** (`clinic_data.SPECIALTIES`:
  прямая запись / по направлению / возраст). Специальность берётся из
  реплики пациента; по симптомам врач НЕ выбирается (симптомы
  озвучиваются — «не комментировать, продолжить запись»); не названа —
  участковый терапевт/педиатр.
- **Сквозной слой безопасности** (`safety.py`) проверяется на каждой
  реплике: красные флаги 7.4 (103/112 + перевод), просьба об операторе,
  жалоба, «вы робот», возражение против записи, острая зубная боль,
  граничные медицинские фразы 3.8.

Контракт NLU: `parse(text, today, options) -> Frame`, где `options` —
список вариантов последнего вопроса ГА (слоты/записи), чтобы модель
могла вернуть `choice` — индекс выбранного варианта.

## Состав

| Файл | Назначение |
|---|---|
| `schema.py` | Frame, интенты (book…other), адресата перевода, действия, итоги звонка |
| `manager.py` | `DialogManager`: приветствие и согласие на запись (3.3–3.4) → диспетчер интентов; сквозные правила, лестница непонимания, тишина, сбои МИС, очередь нескольких интентов |
| `safety.py` | Словарь красных флагов А/Б, оператор, жалоба, зубная боль, медграница; потоки `EmergencyFlow`/`MedicalFlow` |
| `phrases.py` | Эталонные реплики из регламента + таблица FAQ раздела 6 |
| `clinic_data.py` | Таблица выбора врача 2.3 (mode/age), режим работы, синонимы Прил. А.1, часы адресатов |
| `textutils.py` | Вербализация для TTS («в девять тридцать», «кабинет двести четырнадцать») |
| `slots.py` | Детерминированные парсеры: да/нет, даты рождения (А.3), полис, матчинг вариантов |
| `nlu.py` | `RuleNlu` — словарная заглушка; `NatashaNames` — модель имён; `FixtureNlu` — заглушка ФИО для демо; `TaggerNlu` — адаптер теггера `tagger/`; `LlmNlu` — OpenAI-совместимый эндпоинт (json-schema constrained decoding); `FrameModelNlu` — адаптер `train/constrained` |
| `mis.py` | Протокол МИС + `StubMis` на данных примеров скрипта |
| `scenarios/` | `booking` (запись, прямая и по направлению), `appointments` (перенос/отмена/проверка), `info` (график + FAQ), `reminder` (исходящее напоминание); `common` — идентификация и выбор слотов |
| `demo.py` | Консольная REPL: `python -m telephone.demo [--outbound ФАМИЛИЯ]` |

## Запуск

```bash
python -m telephone.demo                # ручной прогон диалога
python -m telephone.demo --outbound Смирнова
```

Дата звонка в демо фиксирована (среда 30.09.2026, как в примерах
скрипта), «завтра»/расписания детерминированы. Пациенты Заглушки МИС:
Смирнова, Петров, Иванов, Кузьмина, Соколов, Смирнова Алиса (7 лет),
Орлова, Никитин (не прикреплён).

## Подключение реальной модели

1. **Frame-модель (train/)** — `FrameModelNlu()` уже работает на полном
   каталоге: 13 интентов + тривиальные да/нет, токенизатор
   `models/tokenizer_v2.json`, e5-резолвер входа включён по умолчанию
   (`TEL_FMODEL_RESOLVER=0` — выключить; для e5 нужен `.venv-tr`).
   Метрики: val exact 0.963, iid 0.925; батарейка из 19 сценариев —
   16 до правильного итога. Чужие для таблицы 2.3 специальности модели
   (dermatologist, psychologist) отбрасываются в словарную страховку.
2. **Теггер (tagger/)** — адаптер `TaggerNlu` готов, но модель знает 4
   интента и 9 специальностей; после переобучения на полный каталог
   расширить `_TOKEN2INTENT`/`_TOKEN2SPECIALTY` в `nlu.py`.
   `<UNSUPPORTED>` — авторитетное решение (`other`): причину не
   разбираем, запрос уходит оператору с текстом реплики.
3. **Готовая LLM** — задать `TEL_LLM_*` и передать `LlmNlu()`: промпт и
   json-схема (constrained decoding) встроены, эндпоинт должен быть в
   контуре заказчика (раздел 8 регламента).
4. **Модель имён (ФИО)** — Natasha (`NatashaNames`) или в составе LLM;
   менеджеру важно только заполненное `Frame.fio`.

## Что вне задачи

Реальная телефония (Asterisk/ASR/TTS), HTTP-сервис, реальная МИС
«Инфоклиника», SMS-шлюз (эмитятся действиями), переобучение NLU-модели,
автотесты (проверка — ручной прогон в demo).
