# Менеджер диалога телефонии (регламент РГ-ТЕЛ-01)

Многошаговый менеджер диалога (МД) голосового ассистента регистратуры по
`скрипт.docx` (регламент РГ-ТЕЛ-01). Чистый Python-модуль без внешних
зависимостей; телфонная часть (ASR/TTS/Asterisk) и МИС подключаются
адаптерами.

## Архитектура: МД — маршрутизатор, разбор реплики — модель

Ключевое разделение ответственности:

- **NLU-модель** (самописная frame-модель или готовая LLM) разбирает реплику
  пациента ЦЕЛИКОМ: интент, специальность, ФИО, дата рождения, полис,
  желаемые дата/время, да/нет, выбор варианта из предложенных (`choice`),
  родство, флаги ветвлений. Результат — `Frame` (`schema.py`).
- **Менеджер диалога** (`manager.py` + `scenarios/`) фрейм не парсит вообще:
  он ведёт FSM по скрипту, задаёт эталонные реплики, выполняет операции
  МИС и эмитит действия (перевод с карточкой, SMS, завершение, обратный
  звонок). Исключение — `policy.py`: сквозные правила безопасности
  (красные флаги 7.4, просьба об операторе, жалоба) как обязательный
  страховочный слой, каким его требует регламент.

Контракт NLU: `parse(text, today, options) -> Frame`, где `options` — список
вариантов последнего вопроса ГА (слоты/записи), чтобы модель могла вернуть
`choice` — индекс выбранного варианта.

## Состав

| Файл | Назначение |
|---|---|
| `schema.py` | Frame, интенты I-01…I-14, сценарии С-01…С-15, правила R-01…R-17, коды результата (Прил. Г), карточка перевода (Прил. В), действия |
| `manager.py` | `DialogManager`: приветствие и согласие на запись разговора (3.3–3.4) → интент → сценарий; сквозные правила, лестница непонимания (R-05), тишина (R-17), сбои МИС (R-06), очередь нескольких интентов |
| `policy.py` | Красные флаги А/Б, оператор, жалоба/благодарность, «вы робот», возражение против записи, зубная боль (R-09), медвопросы (R-04) |
| `phrases.py` | Эталонные реплики из регламента + таблица FAQ раздела 6 |
| `clinic_data.py` | Справочники раздела 2 (режим, специальности прямая/по направлению, ПГГ) |
| `textutils.py` | Вербализация для TTS («в девять тридцать», «кабинет двести четырнадцать») — вывод, не разбор |
| `nlu.py` | `RuleNlu` — словарная заглушка модели (тесты/демо); `FrameModelNlu` — адаптер `train/constrained.generate_frame`; `LlmNlu` — OpenAI-совместимый эндпоинт (env: `TEL_LLM_BASE_URL`, `TEL_LLM_MODEL`, `TEL_LLM_API_KEY`); `FixtureNlu` — заглушка модели имён |
| `slots.py` | Внутренности заглушки: даты рождения (А.3), полис, да/нет, матчинг вариантов. Менеджером диалога НЕ используется |
| `mis.py` | Протокол МИС + `StubMis` на данных примеров скрипта |
| `scenarios/` | Этап 1: С-01/С-02 (запись), С-03/04/05 (перенос/отмена/проверка), С-07 (график+FAQ), С-10 (исходящее напоминание), С-12 (в интересах другого), С-14 (экстренная), С-15 (жалоба). Этап 2 (С-06/08/09/11/13) — распознаются и переводятся с карточкой |
| `demo.py` | Консольная REPL: `python -m telephone.demo [--outbound ФАМИЛИЯ]` |
| `tests/` | Приложение Д (16 контрольных диалогов, блокирующие помечены) + ветвления сценариев |

## Запуск

```bash
cd clinic_lm
.venv/bin/python -m pytest telephone/tests        # 80 проверок
.venv/bin/python -m telephone.demo                # ручной прогон диалога
```

Дата звонка в тестах/демо фиксирована (среда 30.09.2026, как в примерах
скрипта), «завтра»/расписания детерминированы. Пациенты Заглушки МИС:
Смирнова, Петров, Иванов, Кузьмина, Соколов, Смирнова Алиса (7 лет),
Орлова, Никитин (не прикреплён).

## Подключение реальной модели

1. Расширить `synth/vocab.py` на каталог I-01…I-14 и переобучить
   frame-модель → `FrameModelNlu` подхватит её сам (даптер уже готов).
2. Или задать `TEL_LLM_*` и передать `LlmNlu()` в `DialogManager` —
   промпт со схемой фрейма встроен, endpoинт должен быть в контуре
   заказчика (раздел 8 регламента).
3. Модель имён (ФИО) — отдельным сервисом или в составе LLM; менеджеру
   важно только заполненное `Frame.fio`.

## Что вне задачи

Реальная телефония (Asterisk/ASR/TTS), HTTP-сервис, реальная МИС
«Инфоклиника», SMS-шлюз (эмитятся действиями), переобучение NLU-модели.
